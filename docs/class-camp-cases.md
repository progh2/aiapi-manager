## 이해관계자 케이스

### 1. 마이스터고 교사 학급

**상황.** 학기(또는 단원) 동안 명단 전원에게 **같은 금액·같은 기간**의 가상 키를 주고, 수업 중 사용량을 보고, 기간이 끝나면 회수한다. 과제를 더 하는 학생만 충전하거나 기한을 늘린다. 수업 모델만 쓰게 한다.

**교사가 원하는 흐름**

1. 반/조를 고르고 명단(CSV)을 올린다.
2. 인당 예산·만료일(학기 종료일 등)·허용 모델을 한 번에 넣는다.
3. 성공/실패한 학생을 확인하고 키를 나눠 준다.
4. 수업 중 누가 얼마나 남았는지, 누가 소진했는지 본다.
5. 일부 학생만 금액 추가 또는 기간 연장하고, 누가 언제 바꿨는지 남긴다.
6. 기간이 끝나면 그 학급 키를 한꺼번에 막아 더 못 쓰게 한다.

**지금 할 수 있는 것**

- CLI: `scripts/issue_keys.py`로 `name,student_id` CSV → 동일 `--budget` / `--duration` / `--models` / `--team`. 그룹 이름이 없으면 만들고 `--team-budget`을 줄 수 있다.
- UI: 그룹을 먼저 만든 뒤, 한 줄 `학번,이름`을 붙여 넣고 공통 예산·만료·모델을 적용해 `POST /api/keys/bulk`. 끝나면 `alias,api_key` CSV를 받는다.
- 키 목록에서 그룹 필터, 지출/예산 막대, 만료일, 모델, 개별 수정·차단·삭제.
- 대시보드: 기간 총지출, 추세, 선형 예측, 학생별/그룹별 지출.

**막히는 지점**

- UI는 **CSV 파일 업로드가 없고** 붙여넣기만 된다. CLI와 UI의 열 순서가 다르다 (`name,student_id` vs `학번,이름`).
- 만료는 `7d`/`30d`/`90d`/`120d`처럼 **발급 시점부터의 상대 기간**이다. “이번 학기 종업식” 같은 달력 날짜가 없다.
- 이미 있는 별칭은 명시적 건너뛰기가 아니라 LiteLLM 오류를 받아 나머지를 계속 발급하는 방식이다. README의 “건너뛴다”와 동작은 비슷하나, 재발급/갱신 의도와 구분되지 않는다.
- 기간 후 회수는 **키마다** 차단·삭제. 만료된 키만 모아 일괄 회수하는 화면이 없다 (#16).
- 수정 다이얼로그는 예산을 **절대값으로 덮어쓰고**, 연장은 **지금부터 N일**이다. “+$2” 충전이나 기존 만료일에 +2주, 변경 이력이 없다 (#17).
- 모델 체크박스는 키 단위이고 **안 고르면 전체 허용**. 그룹 생성 폼에는 모델 칸이 없다 (#18).

### 2. 중학생 AI 체험캠프

**상황.** 특정일 하루, 인원수만큼 **짧은 랜덤 코드**를 만들어 칠판·인쇄물로 나눠 준다. 저가 모델만 쓰고, 그날 끝나면 자동으로 막힌다. 학번 명단이 없을 수도 있다.

**운영자가 원하는 흐름**

1. 인원 N, 당일 종료, 허용 모델(예: `gpt-4o-mini`만)을 고른다.
2. 타이핑하기 쉬운 짧은 키/코드를 N개 받는다.
3. 인쇄·복사 목록으로 나눠 준다.
4. 그날 자정이 되면 더 이상 호출되지 않는다.

**지금 할 수 있는 것**

- 아무 별칭으로 N번 단건 발급하거나, 가짜 학번 명단을 만들어 일괄 발급.
- 발급 시 모델 체크, CLI `--duration 1d` (UI 선택지에는 **1일/당일 종료가 없음**).
- 예산·RPM으로 남용을 어느 정도 막음.

**막히는 지점**

- 발급 결과는 LiteLLM 가상 키(`sk-…` 장문)다. **짧은 prefix/코드 생성 흐름이 없다** (#19).
- 명단 없는 “N개만 만들어 줘” 화면이 없다.
- 모델 제한은 선택이다. 프록시 설정에는 `gpt-4o`도 있어, 체크를 빼먹으면 비싼 모델이 열린다 (#20).
- UI 만료 선택에 `1d`·당일 자정이 없고, 상대 `duration`은 “지금부터 24시간”이지 **달력상 오늘 끝**이 아니다.
- 만료를 강제하거나 스케줄으로 회수하는 훅이 없다. LiteLLM이 `expires`를 지키더라도, 운영자가 “오늘 캠프”를 한 번에 걸 방법이 없다 (#20).
- 인쇄용 큰 글씨 목록은 없고, 일괄 발급 직후 CSV 한 번이 전부다.

### 3. 운영(Ops) — 잔여 대시보드·일괄 UX

**상황.** 관리자는 학급 필터로 잔여·소진을 보고, 교사가 실수 없이 명단을 넣을 수 있어야 한다. 만료가 가까운 키를 미리 보고 싶다.

**지금 할 수 있는 것 (`main`)**

- 대시보드: 지출 시계열, 예측, 학생/그룹 막대. 키 목록 게이지(소진/임박 80%).
- 일괄 발급: 붙여넣기 → 순차 발급 → CSV. 부분 실패는 `results[].error`로 남는다.
- 키 목록 그룹 필터. 만료일이 지나면 **만료** 뱃지.

**미머지 PR이 더하는 것**

- PR #12: `GET /api/analytics`의 `keyStats`에 `remaining`(`max_budget - spend`), `max_budget`. 예산 없으면 `null`.
- PR #13: 학생 차트에 잔여 문구, 일괄 발급 **성공 N · 실패 M**과 실패 줄 목록, 명단 형식 안내.

**아직 남는 갭**

- `main` 차트/카드에 **잔여** 필드가 없다. #12/#13이 머지되어야 잔여가 보인다 (#21).
- analytics는 **기간 내 지출 > 0**인 키만 그린다. 한 번도 안 쓴 학생의 잔여가 차트에 없다.
- 대시보드 자체에는 학급 필터가 없다. 필터는 아래 키 테이블에만 있다 (#21).
- 만료 **임박** 뱃지/목록이 없다. 지난 키만 붉게 표시 (#22).
- 교사 기준 “3탭 이내” 일괄 발급 전용 흐름은 없다. 단건 폼과 같은 fieldset에 붙어 있다 (#22, #11).

## CLI vs UI 일괄 발급

#11이 정리하라고 한 차이. 학급(#15)과 캠프(#19)를 나누기 전에 맞출 점이다.

| 항목 | `scripts/issue_keys.py` | admin-ui `POST /api/keys/bulk` |
|---|---|---|
| 입력 | 파일 CSV, 헤더 `name,student_id` | 텍스트, 한 줄 `학번,이름`(쉼표·탭·공백) |
| 별칭 | `{student_id}-{name}` | 동일 (`학번-이름`) |
| 그룹 | `--team` 없으면 생성, `--team-budget` | 이미 있는 `team_id`만 |
| 모델 | `--models`, 기본 `gpt-4o-mini` | 체크박스, 없으면 제한 없음 |
| 만료 | `--duration` 임의 (`1d` 가능) | select: 무기한/7/30/90/120일 |
| 결과 | `name,student_id,api_key` 파일 | `alias,api_key` 다운로드 + `results[].error` |
| 기존 별칭 | 실패 후 다음 행 | 동일 (명시적 skip 플래그 없음) |

캠프의 “이름 없는 N개”는 둘 다 1급 기능이 아니다.

### 의존과 권장 순서

1. **#11 / PR #12 / PR #13** — 잔여 필드와 일괄 결과 표시. #21·#22의 기반. #9(NAS 실기)와 병렬 가능하다고 #11에 적혀 있다.
2. **M1 #15 → #18 → #16 → #17** — 먼저 같은 규칙으로 넣고, 모델을 잠그고, 끝나면 회수하고, 예외만 충전·연장.
3. **M2 #20을 #19와 같이** — 짧은 키만 만들고 만료·모델이 느슨하면 캠프 케이스가 성립하지 않는다. 발급 화면에 당일 종료·모델 필수를 기본값으로 두는 편이 맞다.
4. **M3 #21 → #22** — #12/#13 머지 후 학급 필터·0원 키 잔여·임박 목록. #22의 일괄 UX는 #15와 겹치므로 학급 CSV와 캠프 N개를 한 마법사로 합칠지 이슈에서 정한다.

## 현재 스택이 이미 제공하는 기반 (다시 만들지 말 것)

후속 이슈는 LiteLLM 가상 키를 새로 설계하기보다 아래를 감싸면 된다.

- 키: 발급·수정·차단·삭제, `max_budget`, `budget_duration`, `duration`/`expires`, `models`, RPM/TPM
- 그룹(Team): 합산 예산, 키 목록 필터. 개별 한도와 중첩
- 일괄: `POST /api/keys/bulk` 순차 발급, 부분 실패
- 사용량: `/user/daily/activity` → `/api/analytics` (예측은 선형, 3일 미만이면 없음)
- 프록시 모델 목록: `/v1/models` → 발급 체크박스
- 인증: Firebase Google + `ADMIN_EMAILS`

예산 **차단**은 예측이 아니라 LiteLLM 한도가 한다 (README와 동일).

## 결론

`main`은 **키가 있는 학급을 발급하고 지출을 보는 MVP**다. 마이스터고 개강(동일 예산 일괄)은 CLI+UI 우회로 가능하고, 캠프의 짧은 하루 키는 **없다**. 운영이 원하는 잔여 대시보드와 일괄 UX는 #11과 PR #12/#13이 일부를 메우고 있으며, 학급 필터·임박 알림·강제 당일 만료는 남는다.

구현은 M1(학급 예산·회수·충전·모델) → M2(캠프 단축키·당일 만료) → M3(잔여·임박·발급 UX) → M4(테스터) 순으로 #15–#23에 맡긴다.
